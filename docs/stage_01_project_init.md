# 第一阶段：正式项目初始化

## 阶段目标

本阶段的目标是搭建一个正式 Python AI 应用的工程骨架，而不是写一个单文件 Demo。

一个可展示的 RAG 项目不仅要能回答问题，还要让面试官看到你理解工程结构：

- API 如何组织
- 配置如何管理
- 数据库如何连接
- 日志如何统一
- 测试如何编写

## 本阶段完成内容

- 创建 FastAPI 后端项目结构
- 创建 Streamlit 前端目录
- 配置 `.env.example`
- 配置统一日志
- 配置 SQLite + SQLAlchemy
- 实现健康检查接口
- 编写 pytest 测试

## 为什么这样拆目录

`api` 只负责 HTTP 请求和响应，不直接写复杂业务。

`services` 放业务流程，例如后续的文档解析、文本切分、RAG 问答和 Agent Router。

`repositories` 负责数据库读写，避免业务逻辑和 SQL 操作混在一起。

`models` 放数据库表结构，`schemas` 放接口请求和响应结构。

这种拆分能让项目从一开始就具备扩展性。后续新增文档管理、向量索引、问答日志时，不需要推倒重来。

## 健康检查接口

健康检查接口是部署时最常见的基础接口。

路径：

```text
GET /api/health
```

它用于判断服务是否正常启动。以后使用 Docker、云服务器或反向代理时，都可以通过这个接口做存活检查。

## 面试可能追问

1. 为什么不用单文件写 RAG Demo？

回答思路：单文件适合学习，但正式项目需要分层，否则后续知识库、文档、检索、问答、日志都会混在一起，难测试、难维护、难扩展。

2. 为什么先用 SQLite？

回答思路：SQLite 适合本地开发和简历展示，部署简单；通过 SQLAlchemy 做 ORM 后，后续可以较平滑地升级到 PostgreSQL。

3. 健康检查接口有什么用？

回答思路：它可以让部署平台、Docker 编排或运维脚本判断服务是否正常运行，是后端服务的基础可观测入口。
